### MEDIUM

#### M-01 — npm minimum release age is not enforced

- **Location:** `.npmrc:1`
- **Signal:** Semgrep `npm-missing-minimum-release-age`
- **Risk:** A future dependency refresh could resolve a newly published malicious or unstable package before ecosystem detection catches it.
- **Current controls:** committed lockfile, `npm ci`, pinned security-sensitive packages, dependency review, Dependabot cooldowns, CodeQL, Semgrep, and Gitleaks.
- **Remediation:** add `min-release-age=7` after validating the current lockfile and CI toolchain against npm 11.10+; do not introduce an unreviewed dependency downgrade merely to silence the finding.

#### M-02 — Drizzle development tooling retains a vulnerable legacy esbuild

- **Location:** transitive dependency under `drizzle-kit@0.31.10`
- **Advisory:** GHSA-67mh-4wv8-2f99
- **Risk:** The affected behavior concerns an exposed development server. The package is development-only and is absent from the deployed Worker dependency set.
- **Current controls:** production audit reports zero vulnerabilities; development servers are local-only; deployment uses verified build artifacts.
- **Remediation:** track an upstream Drizzle release that removes the legacy `@esbuild-kit` chain. Until then, never expose the development server to an untrusted network.

### LOW / INFORMATIONAL

#### I-01 — Operator recovery ingress is implemented but intentionally undeployed

The connector Worker is private and service-bound. A separate ingress now validates Cloudflare Access RS256 signatures, issuer, audience, expiry, token type, and the exact service-token identity before forwarding through the private connector binding with dual credentials. It remains fail-closed and undeployed until the Access application, team domain, audience, service token, policy, and ingress secrets are provisioned. This is a release blocker rather than an exposed vulnerability.

#### I-02 — Generated artifacts create secret-scan false positives

Whole-tree Gitleaks reports generated Vinext prerender tokens and npm-cache test strings under `dist/` and `.sites-runtime/`. Independent scans of `app`, `connectors`, `lib`, `worker`, `scripts`, and `tests` report no leaks. CI remains scoped to tracked/source material.
